# 验证记录

2026-10-20，Windows PC，Microsoft Edge 155.0.4283.62。使用隔离浏览器配置和自建测试页，未输入到用户现有页面。

## 13 项核心检查通过

原生 INPUT ABI 大小；中文 down/up 对；Unicode 键盘数据；键释放；Emoji UTF-16 对在同一批次；英文扫描码；大写 Shift 释放；Caps Lock 处理；换行停止模式；Shift+Enter 配对释放；Tab 文本输入；自身输入标记；编辑框 CR/LF 标准化。

## 11 项浏览器与桌面流程检查通过

1. 默认 Unicode 模式在真实 Edge textarea 中正确输入中文、英文、Emoji 和多行正文，产生可信 keydown/keyup/input，paste 和 submit 均为 0。
2. 物理键位模式产生 KeyA、KeyZ、Digit0/1/9、BracketLeft/Right、ShiftLeft 的 down/up 配对，并释放修饰键。该模式的文字结果由实际输入法解释，测试不将其当作输入法无关的正文注入。
3. Unicode Tab 保留为正文，不切换焦点。
4. contenteditable 多行正文正确。
5. 显式 Shift+Enter 在 textarea 中正确换行。
6. 实际桌面 UI 逻辑完成倒计时、逐字输入及完成状态，内容一致。
7. F8 中止任务，已输入内容保留，不继续输入。
8. 目标窗口失去焦点时停止。
9. 检测到其他键盘输入时停止。
10. 检测到鼠标点击时停止。
11. “遇到换行停止”仅输入第一行，不发送 Enter。

界面截图另复现并验证了 LF 草稿显示问题：标准化为 Windows CRLF 后，原生文本框正确呈现多行。生产 EXE 由同一源码编译，体积约 19 KB。

## 调试与修复

- 旧编译器命令使用 Windows 反斜杠路径后正常编译。
- 核心测试最初使用了本机未安装的英文键盘布局句柄，查询证实该句柄无法映射；改用实际布局，不改生产输入逻辑。
- 浏览器不把 Unicode LF 或 CR 控制字符当作可靠换行。CR 尝试验证失败后，移除无效方案，采用实际验证通过的显式 Shift+Enter，并提供 Enter 和遇到换行停止选项。
- 混合模式下中文输入法可把真实键位解释成中文标点或拼音候选。保留其真实键位语义，不自动改动用户输入法；原文一致的输入使用默认 Unicode 模式。
- 编辑框只显示 CRLF 的多行正文。先以原生行数断言复现失败，再统一编辑区换行，回归验证通过。

调试遵循 systematic-debugging；以上记录描述已验证的范围，不表示已测试所有第三方网站。
